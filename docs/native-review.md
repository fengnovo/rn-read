# Native document access review

Date: 2026-10-07. Scope: `modules/document-access/**`, the new-file snapshot, and the file-permission requirements in `docs/技术方案.md`.

Verdict: **changes required for spec compliance and code quality**.

- **P2 — renewed directory bookmarks lose the caller's root URI mapping.** `modules/document-access/ios/DocumentAccessModule.swift:112`, `:130`, and `:35`. After a directory moves, `listDirectory(oldRootUri, oldBookmark)` correctly maps the old path to the resolved root and returns a refreshed bookmark. That refreshed bookmark records the new root path, but `DirectoryListing` does not return the new root URI. A caller that persists the refreshed bookmark as documented while retaining its original directory URI fails the next call: the requested URI matches neither the refreshed bookmark's recorded path nor the current scope. Existing valid long-term access becomes unusable after its first stale-bookmark refresh. Return the resolved directory URI and require callers to persist it with the renewed bookmark, or retain the original reference-root mapping independently of renewed bookmark metadata. Include the same treatment for `resolveRelative`, which returns a child URI while renewing its directory bookmark.

Evidence: a focused Foundation probe created a directory bookmark, moved the directory, resolved it (`stale = true`, resolved URL = moved root), and regenerated the bookmark exactly as this module does. With the original requested URI, both the recorded-root prefix condition and resolved-scope containment condition were false on the second request. This checks Foundation path/bookmark behavior on macOS; it does not substitute for device-provider testing. A separate probe confirmed ordinary picker-style minimal bookmarks already expose `.pathKey`, so missing initial path metadata was not reported as a defect. [Apple bookmark resource-value API](https://developer.apple.com/documentation/foundation/nsurl/resourcevalues(forkeys:frombookmarkdata:)).

Other reviewed behavior is consistent with the requested design: SAF document IDs and tree child queries, root security scopes, coordinated iOS reads, bounded stream copies and temporary-file cleanup, decoded relative paths, containment checks, and provider identity keys. The installed Expo 57 module APIs and autolinking configuration align with the implementation.

Existing checks were reviewed rather than rerun. The reported iOS target build and helper checks passed. Android Kotlin compilation remains unverified because the reported Google Maven TLS failure occurred before compiling this module; device permission restoration, cloud providers, and large-file performance also remain pending. These validation limits prevent a claim of complete native acceptance, independently of the code finding above.
